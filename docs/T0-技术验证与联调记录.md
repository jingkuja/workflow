## 1. T0 交付内容

- `boss-workflow-mcp-t0` 与 `employee-workflow-mcp-t0` 两个独立入口。
- Bearer Token 鉴权、角色隔离和不同工具白名单。
- 文档 Base64/HTTPS URL 字段探针。
- 视频 Base64 分块解码、大小、文件头、哈希和落盘探针。
- 随机文件 ID 与公开下载路由。
- 企业微信群机器人 `userid` @探针。
- Nginx 180 MB 请求体、长请求超时和无缓冲 MCP 代理。
- Docker Compose、健康检查、测试和端到端冒烟脚本。

## 3. 本地验证步骤

### 3.1 准备

```bash
cp .env.example .env
docker compose config
docker compose up --build -d
docker compose ps
```

加载测试 Token：

```bash
set -a
source .env
set +a
```

### 3.2 MCP 与文档

```bash
.venv/bin/python -m workflow.scripts.t0_smoke \
  --document "docs/AI行业选题文档上传样例.docx"
```

预期：

- 两个入口都能初始化和 `list_tools`。
- 老板入口包含 `t0_boss_capability`，不包含员工专有工具。
- 员工入口包含 `t0_employee_capability`，不包含老板专有工具。
- Word 文件返回 `opaque_file_id`、SHA-256、大小和下载地址。

### 3.3 视频

```bash
scripts/generate_t0_video.sh t0-artifacts/t0-100mb.mp4
.venv/bin/python -m workflow.scripts.t0_smoke \
  --video t0-artifacts/t0-100mb.mp4
```

登记：

| 指标 | 结果 |
|---|---|
| 原视频字节数 | 100,141,071 |
| Base64 字符数 | 133,521,428 |
| 客户端峰值内存 | 约 792 MiB（本地官方客户端进程） |
| `boss-mcp` 本机进程请求后 RSS | 约 580 MiB |
| `boss-mcp` Compose cgroup 峰值 | 446,066,688 字节，约 425 MiB |
| Nginx 请求总时长 | 0.993 秒（本机 Docker，不代表公网） |
| MCP 客户端工具总时长 | 1.489 秒（经本机 Nginx） |
| 文件 SHA-256 一致 | 是，`ef763ea4…37c4` |
| 下载成功 | 是，100,141,071 字节且哈希一致 |

判定：

- 通过：无 OOM/502/超时，落盘哈希一致，资源余量可接受。
- 降级：WorkBuddy 先上传到可访问位置，工作流 MCP 只接收 URL。
- 禁止：为了勉强通过而取消大小限制或把 Token 放在 URL。

本地结果证明功能链路可行，但也证明 512 MB MCP 容器上限不安全。T0 Compose
已将两个 MCP 容器上限调整为 1 GB；真实 WorkBuddy 测试仍需观察客户端超时、
公网传输和服务端峰值内存，再决定保留 Base64 或使用 URL 降级。

## 5. 企业微信联调

1. 在部署机 `.env` 配置 Webhook 和参与人的 `wecom_userid`。
2. 设置 `T0_ALLOW_WECOM_SEND=true`。
3. 通过老板 MCP 调用：

```json
{
  "message": "企业微信 userid @能力验证",
  "mentioned_userids": ["已在 .env 中登记的 userid"]
}
```

4. 验证群内消息可见、目标成员收到 @，消息未包含 Token、Webhook 或文件内容。
5. 验证后可把 `T0_ALLOW_WECOM_SEND` 恢复为 `false`，等待 T1 通知发件箱实现。

## 6. T0 决策记录

| 决策 | 当前结论 | 复核条件 |
|---|---|---|
| MCP SDK | 使用稳定 `mcp==1.28.1`，不使用 v2 beta | 正式开发前安全修复评估 |
| Transport | Streamable HTTP | WorkBuddy 真实初始化通过 |
| 会话 | T0 使用无会话 JSON response | 只有 WorkBuddy 明确依赖会话/SSE 才调整 |
| Token | 优先 `Authorization: Bearer` | WorkBuddy 不支持时选择安全自定义 Header |
| 视频 | Base64 方案保留为候选 | 100 MB 真实链路通过后确认 |
| 视频降级 | WorkBuddy/外部服务上传，后台收 URL | Base64 OOM、超时或网关不兼容时启用 |
| 文件下载 | T0 使用随机 ID 公开下载 | 正式化时增加鉴权或签名链接 |
