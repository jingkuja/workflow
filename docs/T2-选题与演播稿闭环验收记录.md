# T2 选题与演播稿闭环验收记录

验收日期：2026-07-28

## 交付范围

- 按 Word 中带序号的一级标题顺序拆分选题，提取主爆款标题和提词器口播正文；
  遇到文末非序号核验区停止解析。
- 以原文件 SHA-256 作为导入批次唯一键，并用 PostgreSQL advisory lock 防止并发
  重复创建。
- 创建内容项目、演播稿任务和 `WJ-YYYYMMDD-NNNN` 任务编号。
- 计算工作日有效开始时间，按有效周工作量最小值分配，并列员工随机选择。
- 分配记录只追加增量；取消生效前任务写负增量，改派写原员工负增量和新员工正
  增量。
- 老板可查询批次、删除导入任务、改派、设置优先级、查询员工/项目/待审核任务
  并审核。
- 员工身份只从 MCP Token 解析，可查询本人任务和提交四种格式演播稿。
- 演播稿按版本保存，支持驳回、重新提交和通过；项目详情返回提交与审核历史。
- 导入、分配、取消、改派、提交、驳回和通过均记录审计及通知发件箱事件。

## Code Review 整改（2026-07-28）

- 改派计数口径修复：新员工的 +1 分配事件与原始分配、抵消事件同属
  `effective_started_at` 所在周，跨周改派不再错计。
- 错误码对齐实施方案 §4.1：`RESOURCE_NOT_FOUND`、`INVALID_ARGUMENT`、
  `IDEMPOTENCY_CONFLICT`、`CONCURRENT_MODIFICATION`、`INSUFFICIENT_STORAGE`、
  `NO_ELIGIBLE_ASSIGNEE`、`FILE_TOO_LARGE`、`UNSUPPORTED_FILE_TYPE`、
  `FILE_PROCESSING_FAILED`、`EXTERNAL_DEPENDENCY_FAILED`；workflow-api 的
  401/403/404/参数错误统一返回 `{"success": false, "error": {...}}` 结构。
- 无在岗员工时导入不再整批失败：任务以 `PENDING_ASSIGNMENT` 创建，可后续改派。
- Word 解析改为按文档顺序迭代段落和表格；缺标题/缺正文的选题写入批次
  `parse_report.failures`（迁移 `20260728_04`），批次状态区分
  `COMPLETED`/`PARTIAL_SUCCESS`/`FAILED`，导入响应返回失败明细。
- 幂等保存在唯一约束冲突时回退为重放首次响应（并发重试不再返回 500）。
- 结构化 JSON 日志：API 请求日志（关联 `X-Request-ID`、耗时、状态码）、Worker
  处理结果、MCP 工具拒绝/异常均带 `tool_name` 与 `result_code`；Worker 主循环
  容忍瞬时故障。
- 文档 URL 下载：TCP 连接固定到已校验 IP（关闭 DNS 重绑定窗口），SNI/Host 仍用
  原域名；流式读取并在超过上限时立即中断。
- 新增 `tests/test_pg_integration.py`：真实 PostgreSQL 验证 `SKIP LOCKED` 唯一
  领取、租约超时重领和 advisory lock 互斥，`make test-pg` 运行；postgres 容器
  仅绑定 `127.0.0.1:5432` 供开发机测试。
- 架构回归规格 §3.1：MCP 进程不再直连数据库。13 个业务工具改为
  `WorkflowApiClient` 代理，把原始 Bearer Token 与规范化参数转发到
  workflow-api 的 `/internal/tools/*` 端点；API 用 Token 哈希二次解析身份并按
  端点校验角色（`boss_actor`/`employee_actor`）。`INTERNAL_API_BASE_URL` 默认
  `http://workflow-api:8000`；compose 中两个 MCP 依赖 workflow-api 健康后启动。
- 迁移 `20260727_01`/`20260727_02` 改写为显式 DDL（不再用
  `Base.metadata.create_all`），各 revision 反映当时的历史 schema；已在全新
  PostgreSQL 库验证 `upgrade head` 与 `downgrade base` 双向通过（含枚举清理）。
- workflow-api 内存上限对齐规格 §4.10 调整为 1 GB。

## 边界与运维说明

- 当前人员来自 `.env`，数据库只保存 Token 哈希；人员或 Token 修改后重启服务
  生效。
- 通知默认只写入事务发件箱。只有明确配置企业微信 Webhook 并启用发送后，Worker
  才会真实发送。
- `make compose-up` 会重建全部服务（包括反向代理），避免应用容器重建后 Nginx
  仍缓存旧容器 IP。
- T2 不包含视频上传、剪辑审核和上架闭环，这些属于 T3。
